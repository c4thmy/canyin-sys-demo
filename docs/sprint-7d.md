# 7 天冲刺计划 · 收入分析模块 Demo

**目标**：第 7 天晚上，能在营销课上用一套真实数据、可点击下钻的 Web 系统，讲完「收入为什么涨了 240 万」。
**判定标准**：用户看完会说「这个能卖」。

## 里程碑

| 天 | 主题 | 交付物 | 验收 |
|---|---|---|---|
| D0 | 定方案 | 本仓库、OpenSpec、角色定义、数据字典 | 用户点头 |
| D1 | 数据底座 | `data/*.json` 种子数据 + SQLite schema + 导入脚本 | 数据能进库、能查 |
| D2 | 指标引擎 | 收入结构、同店/新店、连环替代法、渠道漏斗 | 每个指标有单测 + 手算对照 |
| D3 | 看板 v1 | 经营总览（指标卡 + 利润桥瀑布图） | 打开就对，数字对得上 Excel |
| D4 | 下钻 v1 | 收入结构页 + 同店异动页（客流×客单） | 能点进去定位到门店 |
| D5 | 下钻 v2 | 渠道漏斗页 + 产品下钻页 | 能讲清「大众点评为什么 +58 万」 |
| D6 | 结论自动化 | 结论卡片 + 行动计划 + 导出 | 系统能生成一段人能读的结论 |
| D7 | 演示化 | 交互打磨、演示动线、飞书/微信入口、彩排 | 完整讲一遍不出错 |

## 每天的内部节奏

```
上午   产品经理/架构师出当天任务的 specs + design（30 分钟）
       指挥官确认 → 分派
中午   数据/前端并行开发（Worktree Space）
下午   评审官验收 → 指挥官合并 → 推 GitHub
晚间   指挥官用一段人话回微信：今天做完什么、明天做什么、要不要看
```

## 演示动线（营销课 15 分钟版）

1. **开场 2 分钟**：一张总览图。「这家 13 家店的火锅品牌，9 月收入 1000 万，同比 +240 万。问题：这 240 万从哪来？能不能复制？」
2. **利润桥 3 分钟**：瀑布图。「收入贡献 +100.48 万；食材成本率**上升** 1.04 个百分点（25.66%→26.70%），拖累 10.42 万；店铺房租拖累 13.76 万；其它费用拖累 37.00 万。九项合计 +48.10 万，利润从 64.60 万到 112.70 万。」
3. **收入拆解 4 分钟**：新店 143 万 + 同店 97 万。「新店是开店红利，同店 97 万才是真本事。」
4. **下钻 4 分钟**：点「大众点评」→ 漏斗 → 「曝光没涨，访问转化率涨了，因为店铺装修和套餐改版。」再点「肉类」→「销量 +34%，单价没动。」
5. **结论 2 分钟**：系统自动生成一段结论 + 三条行动。「这就是我们说的：比差异、找问题、定计划、达目标。」

## 风险与预案

| 风险 | 预案 |
|---|---|
| 数据口径有争议 | 先按 Excel 口径固化，页面上标注口径，不追求完美 |
| 7 天做不完 | 砍到 4 个页面：总览、收入结构、渠道下钻、结论 |
| 图表太花 | 统一一套配色，只保留瀑布图、漏斗图、柱线组合 |
| 演示环境断网 | 本地 Docker 起，不依赖云 |
| 用户临时加需求 | 进 OpenSpec backlog，不在冲刺内插队 |

## 每天结束要回答的三个问题

1. 今天交付的东西，用户能看懂吗？
2. 数字对得上 Excel 吗？
3. 明天如果只能做一件事，是哪件？

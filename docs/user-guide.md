# 使用说明 · 运行、查看与页面逻辑

本文说明怎么把系统跑起来（本机 / Docker），在浏览器里按什么顺序看，以及每个页面背后的数据逻辑。指标口径以 [domain/revenue-analysis-model.md](domain/revenue-analysis-model.md) 为准。

## 1. 运行

### 1.1 本机

需要 Node.js 22+。

```bash
npm install
npm run dev                  # 开发模式，http://localhost:3000
# 或生产模式
npm run build && npx next start -p 3000
```

`dev` / `build` 脚本已带 `--webpack`，不要去掉。

### 1.2 Docker

需要 Docker Desktop（或 Docker Engine + Compose v2）已启动。

```bash
docker compose up -d --build     # 构建镜像并后台启动，http://localhost:3000
docker compose logs -f web       # 看日志
docker compose down              # 停止（保留导入数据）
docker compose down -v           # 停止并删除导入数据卷（不可恢复）
```

- 演示数据 `data/seed/` 打包进镜像，开箱即用。
- 导入的批次、数据集与报告写在容器内 `/app/data/uploads`，由 compose 的 `uploads` 卷持久化；重建镜像不会丢，`down -v` 会删除。
- 容器以非 root 用户（uid 1001）运行。

冒烟验收：

```bash
bash scripts/smoke.sh            # 本机：构建 + 起 3100 端口 + 断言 13 条路由
bash scripts/smoke.sh --docker   # 容器：compose 构建 + 断言 + 自动 down
```

> `--docker` 模式固定使用 3000 端口。如果本机 3000 已被占用（比如 `npm run dev` 还开着），compose 会报 `address already in use`，先停掉占用的进程再跑。也可以临时换端口：
>
> ```bash
> cat > /tmp/override.yml <<'YML'
> services:
>   web:
>     ports: !override
>       - "3300:3000"
> YML
> docker compose -f docker-compose.yml -f /tmp/override.yml up -d --build   # http://localhost:3300
> ```

### 1.3 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `CANYIN_BASIC_AUTH` | 设为 `用户名:密码` 后全站页面与 `/api` 需 HTTP Basic 登录 | 未设置，不鉴权 |
| `CANYIN_DATA_DIR` | 导入数据目录 | `data/uploads` |
| `PORT` | 服务端口（Docker 内） | `3000` |

Docker 中启用登录：在 `docker-compose.yml` 的 `web` 下加

```yaml
    environment:
      CANYIN_BASIC_AUTH: "demo:换成强密码"
```

> 安全提示：不设 `CANYIN_BASIC_AUTH` 时，上传、回滚、删除等写接口对任何能访问端口的人开放，只适合本机或内网演示。部署到公网必须设置该变量，并在前面加 HTTPS（Basic Auth 明文传输凭据）。

## 2. 在浏览器里看：推荐顺序

### 2.1 先看演示数据（约 5 分钟）

启动后默认是「演示数据」（页头右侧显示「当前数据集：演示数据」）。

1. `/` 经营总览：4 张指标卡 + 利润桥。核对营业利润 112.70 万、同比 +48.10 万。
2. `/revenue/structure` 收入结构：切换同店/新店、渠道、区域、门店四个页签。
3. `/revenue/same-store` 同店异动 → 点任一门店进入 `/revenue/store/S01`。
4. `/revenue/channel`、`/revenue/product`、`/insights` 依次看渠道、产品与自动结论。
5. `/dashboard` 数据看板：KPI 同比 / 环比、趋势、门店排行、数据完整度。演示数据只有 9 月，所以环比显示「—」并注明「无上月数据」。
6. `/reports` → 选「老板版」→ 生成，进入报告预览；试「打印 / 存为 PDF」与「导出 HTML」。

### 2.2 再走一遍导入（约 10 分钟）

1. `/data/templates` 下载需要的模板（建议先下「门店收入」「门店客流」「渠道收入」「利润表」）。
2. 打开 xlsx：第 1 张表填数据（第 2 行以「示例-」开头的是示例，覆盖或保留都行），第 2 张表是字段说明。期间填 `2025-09` 这种月份；金额单位是万元。
3. 多套模板可以放进同一个 xlsx 的不同工作表一次上传，也可以分多次上传。
4. `/data/import`：
   - 第 1 步「上传并解析」：选文件上传。
   - 第 2 步「确认映射」：看每张工作表识别成了哪套模板、每个字段对应哪一列；不对就改下拉框，点「应用映射并重新校验」。
   - 第 3 步「校验报告」：错误（红）必须修完；警告（黄）可以继续，例如收入与客流 × 客单价差异超过 1%。
   - 第 4 步「确认导入」：生效后数据集自动切到「已导入数据」。
5. 回到 `/`、`/dashboard` 看数字变化。缺数据的页面会提示「数据不完整」并列出该导入哪套模板、哪个期间。
6. `/data` 数据中心：可以在两个数据集间切换；批次列表里可以「回滚」已生效批次、「删除」未生效批次。

## 3. 页面逻辑

### 3.1 数据怎么流动

```
演示数据 data/seed/*.json ─┐
                           ├─ loadSeed()（按 active.json 选数据集，按版本号缓存）
导入数据 uploads/dataset/ ─┘        │
        ▲                           ▼
   已生效批次合并              metrics/ 纯函数（算法与数据来源无关）
        ▲                           ▼
 上传 → 解析 → 映射 → 校验      *-view.ts → 页面 / 看板 / 报告
```

- 导入数据最终落成与 `data/seed` 完全相同的文件结构，所以原有 7 个页面的算法不变。
- 「本期」取数据集中最新的月份，「上年同期」是往前 12 个月，「上月」是往前 1 个月。
- 所有页面都是每次请求重新计算（`force-dynamic`），导入或切换后刷新即可看到。

### 3.2 数据处理引擎（`app/lib/ingestion/`）

| 步骤 | 做什么 |
|---|---|
| 上传 | 只收 `.xlsx` / `.csv`，≤ 10 MB、≤ 5 万行，检查文件头魔数；落盘文件名只用批次号 |
| 解析 | xlsx 逐工作表读取；csv 支持引号、引号内换行，自动识别 UTF-8 / GBK；保留原始行号 |
| 识别映射 | 在前 10 行里找表头，按「完全匹配 > 别名（如营业额→收入）> 去单位空格后匹配」识别模板与列；可手工改 |
| 校验 | 错误（阻断）：必填、类型、期间格式、负数、主键重复。警告：收入 vs 客流 × 客单价、渠道合计 vs 门店合计（> 1%）、单店收入数量级、漏斗逐级递减、利润表科目不全 |
| 生效 | 所有已生效批次按生效先后合并，同一「模板 + 主键 + 期间」后到覆盖先到；同一文件导入两次结果不变 |
| 回滚 | 批次标为已回滚后重新合并；全部回滚后自动回到演示数据 |
| 追溯 | `dataset/lineage.json` 记录每个数字来自哪个批次、文件、工作表、行号 |

### 3.3 页面清单

| 路由 | 回答什么问题 | 需要的模板（本期 + 上年同期） |
|---|---|---|
| `/` 经营总览 | 收入多了多少，利润为什么变化 | 利润表、门店收入 |
| `/revenue/structure` | 增量来自新店还是老店、哪个渠道和区域 | 门店收入、渠道收入 |
| `/revenue/same-store` | 老店靠客流还是客单价 | 门店收入、门店客流 |
| `/revenue/store/[id]` | 单店三项对比与同店横向比较 | 门店收入、门店客流 |
| `/revenue/channel` | 渠道收入同比、获客效率 | 渠道收入、门店收入 |
| `/revenue/product` | 系列销量结构变化 | 产品销售 |
| `/insights` | 自动结论与三条行动建议 | 上述五项 |
| `/dashboard` | 多期趋势与完整度 | 有什么显示什么 |
| `/data` · `/data/templates` · `/data/import` | 数据集、模板、导入 | — |
| `/reports` · `/reports/templates` · `/reports/[id]` | 生成与查看报告 | 按章节各自判断 |

- 缺任一所需模板时，整页换成「数据不完整」提示，列出缺失的模板与期间，并给出「前往导入数据 / 下载模板 / 切换数据集」入口。
- 时段客流、获客、套餐三类数据本期不开放导入；用导入数据时，同店页的时段面板、渠道页的获客成本、产品页的套餐分解为空。

### 3.4 数据看板（`/dashboard`）

- 门店收入 = Σ 门店收入；客流 = Σ 门店客流；客单价 = 门店收入 × 10000 ÷ 客流（按客流加权）；营业利润 = 营业收入 − 8 项成本费用。
- 同比、环比在对比期无数据或为 0 时显示「—」，并在卡片下写明原因。
- 完整度矩阵：6 套模板 × 各期间，「缺失」格可直接点进导入页。

### 3.5 分析报告（`/reports`）

- 两套模板：老板版 4 章（执行摘要、利润桥、收入异动原点、三条行动建议）；运营版 8 章（加上收入结构、同店异动、渠道、产品、结论清单、行动计划）。章节目录见 `/reports/templates`。
- 章节里的数字全部取自对应页面的计算，保证报告与页面一致；叙述由模板拼接，不调用大模型。
- 某章所需数据缺失时，该章显示「数据不足，本章略」并列出缺什么，其他章节照常生成。
- 生成时连同图表（服务端渲染的 SVG）整体保存为快照，之后导入或回滚都不会改变已生成的报告。
- 「打印 / 存为 PDF」隐藏导航和按钮，每章另起一页；「导出 HTML」下载单个离线文件，无脚本。

## 4. 常见问题

- **上传后提示「缺少必填字段」**：表头没被认出。到第 2 步把对应字段手工指到正确的列，或改成模板里的表头名。
- **收入看起来大了一万倍**：把「元」填成了「万元」。校验会给出数量级警告，回滚批次、改正后重传。
- **页面一直是演示数据**：看页头的数据集标识；到 `/data` 切到「已导入数据」。只有存在已生效批次时才能切换。
- **只导入了 10 月**：本期变成 2025-10，上年同期 2024-10 没有数据，分析页会提示缺失；看板仍可显示 10 月的值。
- **想清空导入数据**：在 `/data` 把所有已生效批次回滚（可再删除）；Docker 下也可以 `docker compose down -v`。

# Design

## Context

`@xmanrui/dsh-im` 已安装在 desktop profile，微信通道已有绑定账号。飞书通道需要一份飞书开放平台的应用凭据（App ID / App Secret），由用户授权后由机器人长连接接收消息。

## Goals / Non-Goals

**Goals:**

- 10 分钟内完成飞书接入
- 与微信共用同一项目工作区与规格
- 凭据只存本机，不进仓库

**Non-Goals:**

- 不做多租户机器人
- 不做网页端嵌入

## Decisions

### 决策一：优先扫码创建，其次手工填凭据

扫码由飞书开放平台自动创建企业自建应用，省去权限配置。手工方式作为备选，用于已有应用的企业。

### 决策二：凭据不落仓库

凭据存放在 DSH 的设置存储中，`.gitignore` 已排除 `.env`。

## Risks / Trade-offs

- **企微/飞书管理员审批** → 若企业不允许自建应用，改用群机器人 Webhook（只发不收）
- **长连接不稳定** → 保留微信通道作为备份
